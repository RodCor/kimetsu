# Kimetsu v0.2-rc1 — Ship Notes

**Tag**: `v0.2-rc1` (commit `09ba266` on `main`)
**One-line**: kimetsu wraps Claude Opus 4.7 as a budget-controlled
coding agent at ~5% of bare Claude Code's cost on Terminal-Bench 2,
with a curated-memory brain that's marginally cheaper and ties bare
no-brain on accuracy.

## What v0.2 delivers

- **Harbor / Terminal-Bench integration end-to-end** (MP-7 through
  MP-9). `harbor run --agent-import-path
  kimetsu_harbor.kimetsu_agent:KimetsuAgent` drives the kimetsu
  binary inside Harbor's container; the model emits JSON envelope
  tool calls; kimetsu routes each as a `tool.exec` JSON-RPC frame
  to Harbor's `environment.exec`; the verifier scores.
- **Human-curated memory pipeline** (MP-5 / MP-6). Replaces v0.1's
  auto-accept policy with `kimetsu brain memory review` for
  interactive curation + `memory top` / `memory prune` for
  usefulness-driven hygiene.
- **7-tool composed surface in Rust** (MP-12). `read_file`,
  `list_files`, `search_files`, `write_file`, `git_status`,
  `git_diff`, `shell_command` — each implemented as a composed
  shell call through `HarborShellExecutor`. The model sees
  first-class JSON tools; under the hood every operation routes as
  a tool.exec JSON-RPC frame.
- **Harness improvements** (MP-13 a/b/c/d). Auto-orient the model
  with one shell call before the first turn (saves 3-5 orientation
  turns per task); turn budget 25→40; Claude Code `--max-turns`
  8→16; persistence gate that nudges the model when it tries to
  finish after fewer than 3 tool calls.
- **Resilient claude_code provider** (MP-13f). Retry on transient
  Anthropic 5xx errors (≥500 status or "Overloaded" sentinel) with
  5s/10s exponential backoff. MP-13e caught a 14-of-16 trial
  catastrophic outage that retry fully absorbed in MP-13g.

## V0.2 falsifiable claim — gate-by-gate

The V0.2-PLAN.md ship criteria:

1. **kimetsu-brain ≥ kimetsu-no-brain on Terminal-Bench accuracy** —
   ✓ **passes** (tie at 0.375 = 6/16 on the curated 16-task slice).
   The brain unlocks `compile-compcert` (a task no kimetsu mode
   previously solved) while losing `break-filter-js-from-html`
   (within n=16 variance).

2. **kimetsu-no-brain within 5pp of bare Claude Code** —
   ✗ **fails** at -18.75pp (0.375 vs bare's 0.5625). Structural:
   bare CC has the full Bash/Edit/Read/Glob/Grep/Write toolset
   plus its own agentic loop. Closing this gap is MP-14
   (v0.2-rc2 / v0.3 work — see Roadmap below).

3. **Three consecutive runs within ±5pp** —
   ✓ **passes for no-brain**. MP-10 and MP-13 no-brain both landed
   at exactly 0.375 on identical 16 tasks across two independent
   runs days apart. The brain leg is noisier (MP-11 0.40, MP-12
   0.3125 contaminated by parallel-load, MP-13g 0.375).

**v0.2-rc1 ships on gates 1 + 3** with gate 2 acknowledged as a
v0.3 structural problem.

## Cost asymmetry — the actual v0.2 value prop

Bare Claude Code on the same 16 tasks costs **$22.24**. Kimetsu-brain
costs **$1.09** — a **20× cost reduction** at 67% relative accuracy.
For the tasks kimetsu wins, $/win comes in at $0.18 vs bare's $2.47
(a **14× cheaper win**). This is the MEMORY-USEFULNESS.md Scenario-2
prediction holding cleanly: similar accuracy on the right tasks,
much cheaper.

## Architectural decisions, recorded

- **External Python adapter** (option A in V0.2-PLAN MP-7). The
  kimetsu binary stays the single source of truth; `kimetsu_harbor`
  is a 250-line Python wrapper implementing Harbor's `BaseAgent`.
- **Envelope grammar in the user message, not system prompt** (MP-9).
  Claude Code 2.x's `-p` mode injects its own agentic harness over
  `--system-prompt`; the user message is the only authoritative
  place for our tool grammar.
- **Composed Rust tools, not direct shell** (MP-12). Each tool is a
  Rust shim that builds 1-2 shell calls through HarborShellExecutor
  and returns structured JSON. The model never sees the underlying
  bash, which cuts both token cost and "wrong flag" failure modes.
- **Brain mode as a curated-memory feature, not auto-accept** (MP-5).
  The MP-4 verdict killed auto-accept; v0.2 ships the
  `kimetsu brain memory review` human-curation flow with a project
  pointed at by `--project` / `$KIMETSU_HARBOR_PROJECT`.

## What's NOT in v0.2 (deferred)

- Closing the bare-CC accuracy gap (-18.75pp). Requires widening
  the kimetsu tool surface beyond composed-shell to include CC-
  and Codex-style primitives (Edit/MultiEdit, apply_patch,
  multi-tool envelopes). MP-14.
- Per-task instruction-aware memory selection. Currently memories
  are retrieved by query string against the task description; a
  task-type classifier could pick more relevant capsules.
- v0.2 stability over a full week per V0.2-PLAN literal text. We
  have two same-day runs at exact tie; running the bench daily for
  a week and recording variance is straightforward but hasn't been
  done.

## Roadmap

- **MP-14**: widen tool surface to close gate 2.
  - 14a: `edit_file` / `replace_in_file` (CC Edit + MultiEdit
    equivalent). Hash-checked in-place replacement; multi-edit
    batches.
  - 14b: `apply_patch` accepting unified diff (Codex's signature).
  - 14c: multi-tool envelopes — model can request several tool
    calls per turn, executed serially or in parallel.
  - 14d: re-run the gauntlet, measure gate 2 closure.

- **MP-15**: time-series stability run — once per day for a week,
  capture variance, lock the gate 3 evidence.

- **MP-16 (maybe)**: per-task memory selection. Cluster tasks by
  type, route different capsule sets per type.

## How to use v0.2

```bash
# One-time setup (see kimetsu_harbor/SETUP-WSL.md for full WSL2 path)
pip install harbor
cargo build -p kimetsu-cli --release

# Curate a memory pool
kimetsu init
kimetsu brain memory add --scope global_user --kind preference "..."
kimetsu brain memory review               # interactive review of proposals
kimetsu brain memory top --min-uses 3     # see what's pulling weight
kimetsu brain memory prune --apply        # clean up underperformers

# Run Terminal-Bench (brain mode)
export KIMETSU_BIN=$(pwd)/target/release/kimetsu
export KIMETSU_HARBOR_PROJECT=$(pwd)
harbor run \
  -d terminal-bench/terminal-bench-2 \
  --agent-import-path kimetsu_harbor.kimetsu_agent:KimetsuAgent \
  -n 2 -k 1 --yes
```
