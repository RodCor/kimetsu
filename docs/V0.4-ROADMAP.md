# v0.4 Roadmap — best-in-class brain sidecar + cross-harness bridge

Goal: make kimetsu the unambiguous choice when a user wants
durable memory + portable skills + a cross-harness bridge for
Claude Code / Codex. Each item is shippable as a single PR.

Status legend:
- `[planned]`  on the roadmap, not started
- `[wip]`     work-in-progress (kimetsu branch exists)
- `[shipped]` landed on `main`
- `[deferred]` intentionally not in v0.4

---

## Tier 1 — Brain (memory layer)

### 1. Embeddings + hybrid retrieval — split across two ships
**`[shipped]` v0.4.2 (scaffolding)** + **`[shipped]` v0.4.3 (fastembed + reindex)**

v0.4.2 landed:
  * `kimetsu_brain::embeddings` module: `Embedder` trait,
    `NoopEmbedder` (production default), `StubEmbedder` (test-only,
    deterministic), cosine + BLOB codec helpers.
  * Schema: `memories.embedding BLOB NULLABLE`,
    `memories.embedding_model TEXT NULLABLE`. Migrated in-place via
    the existing `add_column_if_missing` idempotent ALTER pattern.
  * Write path: `add_memory` and `add_user_memory` call
    `embed_and_persist` post-projection. Pre-v0.4.3 the default
    embedder is Noop so the column stays NULL — exact v0.4.1
    behavior.
  * Retrieval path: `retrieve_context_with_embedder` blends cosine
    with FTS as `final = (1 - α) * lex + α * normalized_cos` with
    `α = DEFAULT_HYBRID_ALPHA (0.5)`. Cross-model rows skip the
    cosine term and fall back to lexical (so v0.4.3 reindex
    migrations stay safe mid-flight). NULL embeddings + Noop
    embedder skip the blend entirely.
  * 13 new tests covering cosine math, BLOB round-trip, stub
    determinism, retrieval blend, model-id mismatch fallback, Noop
    regression-guard.

v0.4.3 landed:
  * `fastembed = "5"` added as an OPTIONAL dependency behind the
    `embeddings` Cargo feature. Default build (no feature) stays
    dep-light and keeps the NoopEmbedder path — `cargo install
    kimetsu-cli` doesn't pull ONNX runtime or model files.
  * `FastembedEmbedder` (cfg-gated): wraps `fastembed::TextEmbedding`
    in a `Mutex` for shared use across REPL threads. The cached
    ONNX session is opened once via a `OnceLock`.
  * `open_default_embedder()` returns the cached embedder.
    Resolution order:
      1. `KIMETSU_BRAIN_EMBEDDER=noop|off|none|0|false|no` → force
         NoopEmbedder regardless of feature flag.
      2. `--features embeddings` build → fastembed-backed embedder.
      3. Default build → NoopEmbedder.
  * Three builtin models reachable via `KIMETSU_BRAIN_EMBEDDER`:
      - `bge-small-en-v1.5` (default; 384-dim, ~67 MB int8, English)
      - `bge-m3` (1024-dim, ~600 MB int8, multilingual)
      - `jina-v2-base-code` (768-dim, ~165 MB int8, English + code)
    Model-load failures (network, disk, ort runtime missing) fall
    through to Noop with a one-line warning — retrieval keeps
    working on FTS alone.
  * `kimetsu brain reindex [--scope project|user|all] [--dry-run]
    [--force] [--limit N]` backfills NULL embeddings AND rows
    whose `embedding_model` doesn't match the active embedder. Walks
    both the project DB AND the user brain DB at `~/.kimetsu/brain.db`
    introduced by v0.4.1.
  * 11 new tests:
    `env_disables_embedder_recognizes_off_values`,
    `pick_builtin_model_from_env_handles_aliases`, +
    `reindex_scope_parser_accepts_aliases` + four reindex E2E
    tests against StubEmbedder, + a `cargo check --features
    embeddings` smoke build that exercises the fastembed compile
    path (no model download, no inference).

### 2. User-scope brain at `~/.kimetsu/brain.db` `[shipped]` (v0.4.1)
Today `MemoryScope::GlobalUser` lives in the workspace's
`.kimetsu/brain.db`. Open a second repo and the memories don't
follow. Add `~/.kimetsu/brain.db` for user-scope capsules. Reads
merge from both DBs; writes route by scope.

### 3. Decay + conflict detection `[planned]`
Memories rot. Two capsules contradict and we silently inject both.
- `last_useful_at` + usefulness half-life applied at retrieval time
  (not destroy-on-disk).
- At ingest, run a cheap contradiction check against top-K nearest
  existing capsules — surface as a proposal, not an auto-accept.

### 4. Ambient context the host doesn't have to ask for `[shipped]` (v0.4.4)
v0.4.4 landed:
  * `kimetsu_brain::ambient` module: collects git branch
    (`git rev-parse --abbrev-ref HEAD`), top entries of
    `git status --short`, top-5 mtime-ordered recently-modified
    files (via the `ignore` crate, filtering `.kimetsu/`). All
    collection is best-effort with a 2s git timeout and a 150ms
    walker budget — total ambient collection budget is ~50ms on a
    warm repo.
  * `render_as_query_suffix(&ctx) -> String` produces a short,
    lexically + semantically retrievable suffix like
    `\n[workspace: branch=feature/x | recent: a.rs, b.rs |
    dirty: M a.rs, ?? c.rs]` that's appended to the explicit
    `query` before retrieval.
  * `kimetsu brain context [--no-ambient] [--json]` auto-augments
    by default; the JSON output gains `augmented_query` and
    `ambient` fields so hook consumers see what was used.
  * MCP `kimetsu_brain_context` and `kimetsu_benchmark_context`
    tools accept an optional `include_ambient: bool` (default true)
    + honor `KIMETSU_BRAIN_AMBIENT=off`. The benchmark path uses a
    new `retrieve_benchmark_context_readonly_with_ambient` wrapper
    that appends the suffix AFTER slug detection so
    `normalize_task_slug` isn't confused.
  * Future-proofing: v0.4.3's semantic retrieval makes the suffix
    much more useful than it would have been pre-embeddings —
    branch names, file paths, and dirty-line text all embed and
    contribute cosine signal alongside the explicit query.

Disable: `KIMETSU_BRAIN_AMBIENT=off|0|false|no|none` (global) OR
`include_ambient=false` on the MCP call OR `--no-ambient` on the
CLI.

### 5. Citations + blame `[planned]`
When the model uses a memory, expect it to write back
`used_memory_ids: [...]`. Then `kimetsu brain memory blame <run-id>`
answers "which memory pushed me wrong". Today the only signal is
`run.failed` -> -1.

### 6. Secret redaction at ingest `[planned]`
A model writing a tool-result containing
`CLAUDE_CODE_OAUTH_TOKEN=sk-...` into an episodic memory is a
permanent leak. Regex+entropy redactor in the ingest path. Easy,
no-regret.

## Tier 2 — Bridge (cross-harness)

### 7. Conversation handoff format `[deferred]` (post-v0.4)
"Started in Claude Code, continue in Codex." Today: copy-paste.
Define `kimetsu://transcript/<id>` as canonical JSON the bridge can
write from CC's session log and CC can resume from. Deferred:
host CLIs change their transcript formats frequently; wait for MCP
`conversations` if/when standardized.

### 8. MCP server federation `[planned]`
A user has 4 MCP servers registered in Claude (filesystem, github,
postgres, slack). Kimetsu's `/mcp` only sees what kimetsu itself
connects to. Expose `kimetsu_mcp_federate` so kimetsu can sit on top
of the host's other MCP servers and re-export them to the other
harness.

### 9. Skill lint + normalize on import `[planned]`
Codex skills sometimes use Codex-only patterns (apply_patch shape),
Claude skills use Claude-only ones (XML envelopes). `bridge import`
should detect and rewrite.

### 10. Skill lockfile `[planned]`
`.kimetsu/extensions.lock` recording
`{name, source_root, source_sha, imported_at}`. Then `bridge sync`
can say "your reviewer skill is from `~/.codex/skills/reviewer@abc123`,
upstream is now `@def456`, re-import?". Today drift is invisible.

### 11. Provider routing `[deferred]` (post-v0.4)
"Plan with opus, edit with sonnet, verify with haiku." Expose
`kimetsu_route_completion` so a skill can declare per-stage models.
Deferred: not needed to win the brain-sidecar pitch; the bridge
can keep claude_code as the default.

### 12. Cross-harness cost budget `[deferred]` (post-v0.4)
A user's "$50/day across all my agents" lives in
`.kimetsu/budget.json`. Pre-turn hook denies on overrun. Deferred:
wait for two real complaints from users hitting it across CC +
Codex simultaneously.

## Tier 3 — MCP protocol surface (easy wins)

### 13. MCP `resources` (not just `tools`) `[planned]`
You're using only one of MCP's three primitives. Add:
- `kimetsu://memory/<id>` — read one capsule
- `kimetsu://playbook/<task-slug>` — direct read for benchmark playbook
- `kimetsu://repo-manifest/<path>` — repo structure

Host can `read_resource` lazily instead of calling
`kimetsu_brain_context` and parsing the wrapped response.

### 14. MCP `prompts` `[planned]`
Pre-canned prompts the host's command palette can offer:
`kimetsu://prompt/security-review`, `kimetsu://prompt/dogfood-bench`.
Discoverable without the user knowing they had a kimetsu skill
loaded.

### 15. Notifications instead of polling `[planned]`
MCP supports SSE-style notifications. When a memory proposal is
accepted or a memory is invalidated, the host should be told —
not have to poll on next turn.

## Tier 4 — Cross-cutting (table-stakes for "best in class")

### 16. Distribution path `[planned]`
Today "clone the repo, `cargo build`" is the only way in. Ship:
- `cargo install kimetsu-cli` (publish to crates.io)
- `brew install kimetsu` / `scoop install kimetsu` /
  `npm i -g @kimetsu/cli`
- GitHub Releases binaries

The `plugin install` UX is wasted if the user can't `kimetsu`
from anywhere.

### 17. `kimetsu doctor` that validates the wire `[planned]`
Today `bridge doctor` reads files. A proper doctor:
- spawns `kimetsu mcp serve`
- issues a `tools/list` over its own stdin/stdout
- calls `kimetsu_brain_context` with a dummy query
- confirms the pre-turn hook executes when fired
- reports red/yellow/green with an actionable fix.

### 18. Sandbox tool execution by default in MCP mode `[planned]`
When CC/Codex calls kimetsu's `/run`-equivalent through MCP,
kimetsu inherits the host's permissions. For sidecar mode it
should run shell commands in Bubblewrap (Linux) / sandbox-exec
(Mac) / AppContainer (Windows) by default. Users opt out
per-tool.

### 19. Local eval harness `[planned]`
"Did this new memory help?" needs an A/B answer that isn't
"wait for the next Terminal-Bench gauntlet". Add
`kimetsu eval suite --memory-set <id>` that runs a small fixed
task set with the memory subset ON vs OFF and reports cost-per-win
delta.

### 20. Telemetry export `[planned]`
OpenTelemetry traces + Prometheus metrics from `kimetsu mcp serve`.
Teams adopting kimetsu in an enterprise context need to see cache
hit rate, per-call P95 latency, accepted/rejected proposal counts.
Today this lives in `.kimetsu/runs/*.jsonl` and is hostile to
aggregate.

|-------|------|-------------|-------------------|
| **week 1** | #2 user-scope `~/.kimetsu/brain.db` | v0.4.1 ✅ | "brain that follows you between projects" is the core pitch; today it's broken |
| **week 1** | #1a embeddings + hybrid retrieval (scaffolding) | v0.4.2 ✅ | infrastructure for semantic retrieval, behind Noop default |
| **week 1** | #16 distribution path | v0.4.1.1 | nothing else matters if onboarding is "clone + build" |
| **week 2** | #1b fastembed-rs backend + brain reindex CLI | v0.4.3 ✅ | finally ships the value (`cache_read` of semantic kind) |

| **week 3** | #13 + #14 MCP resources + prompts | v0.4.3 | cheap, makes kimetsu visible in CC/Codex command palettes |
| **week 3** | #6 secret redaction at ingest | v0.4.3 | one leak = "never installing kimetsu again" |

## Explicitly deferred past v0.4

- **#7 conversation handoff** — host CLIs change transcript formats
  frequently; wait for MCP `conversations` standardization.
- **#11 multi-provider parity / routing** — not needed to win the
  brain-sidecar pitch; bridge keeps claude_code default.
- **#12 cross-harness cost budget** — wait for real user complaints.
- **#18 sandbox tool execution** — important but Bubblewrap /
  sandbox-exec / AppContainer are three separate implementations
  with different security models. Land after #17 doctor so we
  can validate behavior end-to-end.
- **Web dashboard / GUI** — terminal-first is fine; do it after
  telemetry export (#20).

## The single biggest gap (if asked to name one)

**#1 (embeddings) + #2 (user-scope brain) together.** Right now a
user installs kimetsu in two repos, the brains don't talk, AND
retrieval misses semantically-close-but-lexically-different
queries. Those two together make the difference between "an
interesting brain plugin" and "I cannot work without this anymore".

That's why v0.4.1 + v0.4.2 are the first two commits.
