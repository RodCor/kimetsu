# v0.5 — the brain learns from outcomes

v0.4 made kimetsu real (user-scope brain, hybrid retrieval, ambient
context, redaction, distribution). v0.5's north star is making the
brain *get smarter over time* from real run data instead of staying
at the same quality forever.

Three commits, shipped iteratively:

| ship | item | what changes | user-visible |
|------|------|--------------|--------------|
| **v0.5.0** | #5 citations + blame | model marks which memories it actually used per turn | `kimetsu brain memory blame <run-id>` shows attribution |
| **v0.5.1** | #3 part 1 — decay | usefulness multiplier degrades over time | stale memories rank lower without manual pruning |
| **v0.5.2** | #3 part 2 — conflict | new memory checked against existing similar capsules at ingest | contradictions surface as proposals, not silent additions |

Each commit is independently shippable and crates.io-publishable.
The arc is designed so v0.5.0 generates the attribution data that
v0.5.1's decay uses, and v0.5.2's conflict detection uses both
attribution AND the embedder shipped in v0.4.3.

## Why this arc

Today the brain's usefulness signal is **per-run, all-or-nothing**:

* `run.finished` with success → every memory in the
  `context.injected` event gets `+1 usefulness, +1 use_count`
* `run.failed` (excluding gate failures) → every memory in the
  context gets `-1 usefulness, +1 use_count`

That's noisy. A run that succeeded thanks to 1 of 10 retrieved
memories rewards all 10 equally. A run that failed despite a
correct memory penalizes that memory unfairly. The retrieval
broker uses this score to bias future picks — wrong attribution
compounds.

v0.5 fixes this by giving the model a way to say which memories it
**actually** used in its reasoning, and tightening the
usefulness loop around that signal.

## v0.5.0 — citations + blame

### What the model gains

A new tool: `cite_memory(memory_id, rationale?)`. The model calls
it during a turn when it consciously leveraged a retrieved
capsule. Example:

```text
turn 3:
  thought: "The brain returned a memory about ripgrep being
            preferred over grep. I'll cite it before I run rg."
  tool_calls:
    - cite_memory(memory_id="m_01J9XYZ", rationale="using rg pattern from memory")
    - shell_command(program="rg", args=["pattern", "src/"])
```

Multiple citations per turn are fine. Citations are best-effort —
nothing fails if the model forgets to cite.

### What the brain stores

New table:

```sql
CREATE TABLE memory_citations (
    run_id     TEXT NOT NULL,
    memory_id  TEXT NOT NULL,
    turn       INTEGER NOT NULL,
    cited_at   TEXT NOT NULL,
    rationale  TEXT,
    PRIMARY KEY (run_id, memory_id, turn)
);
CREATE INDEX idx_citations_run ON memory_citations (run_id);
CREATE INDEX idx_citations_memory ON memory_citations (memory_id);
```

New event kind: `memory.cited` with payload
`{memory_id, rationale, turn}`. The projector inserts the row.

### Usefulness scoring upgrade

`projector::apply_run_finished` and `apply_run_failed` switch from
"every memory in context.injected gets ±1" to:

* **Cited memories** get the full ±1 delta (matches today).
* **Uncited but retrieved memories** get a tiny ±0.1 delta
  (still some signal — they were on screen, the model could have
  used them).

Total signal per run is conserved on average, but cited memories
get the strong signal and silent passengers get the weak one.

### `kimetsu brain memory blame <run-id>` CLI

```text
$ kimetsu brain memory blame 01J9XYZABC
[blame] run 01J9XYZABC — terminated: success, cost $0.12
[blame] task: refactor src/parser.rs to use thiserror

  cited memories:
    m_pref_001  rg over grep                    cited@turn=3 (rationale: "using rg pattern from memory")
    m_conv_007  prefer thiserror for libs       cited@turn=7 (rationale: "matches the requested refactor")

  retrieved but not cited:
    m_pref_002  use cargo nextest
    m_conv_012  imports go in std/third/local order

[blame] suggested updates:
  +1.0 usefulness on m_pref_001, m_conv_007 (cited + run.finished)
  +0.1 usefulness on m_pref_002, m_conv_012 (retrieved, not cited)
```

The MCP equivalent: a new `kimetsu_brain_memory_blame` tool.

## v0.5.1 — decay

Memory rot is real. A capsule that helped 10 runs 6 months ago
shouldn't outvote a capsule that helped 1 run yesterday. v0.5.1
adds time-aware weighting:

* New column: `memories.last_useful_at TIMESTAMP NULL`. Bumped on
  every `memory.cited` event that ended in `run.finished`.
* `usefulness_multiplier` (in `context.rs`) gains a decay term:
  `effective_score = raw_score * exp(-age_days / half_life)`
* New broker config: `decay_half_life_days = 30` (default).
* `kimetsu brain memory list --include-aged` to surface what's
  decaying.

The decay applies at retrieval, not at storage. A memory's raw
`usefulness_score` doesn't change; the broker just weights it
lower when it's old. `kimetsu brain memory prune --max-age 180`
becomes a useful operator command.

## v0.5.2 — conflict detection at ingest

Two memories that say opposite things ("use thiserror" /
"use anyhow") confuse the model when both are retrieved. v0.5.2
detects contradiction at ingest time:

1. When `add_memory` is about to insert text T with scope S,
   compute T's embedding via the active embedder.
2. Query the top-3 nearest existing capsules in scope S by cosine.
3. If any pass `conflict_threshold = 0.8` similarity AND their
   normalized text differs from T → flag conflict.
4. Instead of auto-accepting, surface as a memory proposal with
   rationale "conflicts with memory_X: <text>".
5. The user reviews via the existing `kimetsu brain memory review`
   flow; accepting the new one optionally invalidates the old.

Conflict detection only runs when an embedder is available
(opt-in via `--features embeddings`). With NoopEmbedder it's a
no-op — the v0.4 lexical-dedup logic stays unchanged.

## What's NOT in v0.5

* Multi-provider routing (v0.4 roadmap #11) — deferred.
* MCP federation (#8) — deferred to v0.6.
* MCP resources/prompts (#13/#14) — deferred.
* Cross-harness budget (#12) — wait for user complaints.

The v0.5 ship is brain-internal: smarter usefulness signals,
smarter aging, smarter ingestion. After it lands, the brain
sidecar pitch sharpens from "memory that follows you" to "memory
that follows you AND improves on its own."

## Validation

After v0.5.2:

1. Run 10 chat sessions against the kimetsu repo.
2. Check `kimetsu brain memory blame` for each — should show real
   citations, not "no memories cited."
3. Let it cook for a week; check `kimetsu brain memory top` —
   the top should reflect what actually helped, not what was
   retrieved most often.
4. Try to add a contradicting memory; confirm it's flagged.
