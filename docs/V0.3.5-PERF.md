# v0.3.5/v0.3.6 Performance Passes

Implemented after the Harbor/product CLI split.

## Changes

- **Chat auto-orientation runs only on the first model turn.** Later turns
  keep the conversation transcript and brain retrieval, but no longer pay the
  extra shell call and repeated prompt bytes for the same workspace snapshot.
- **`kimetsu chat` defaults Claude persistent mode on.** The global
  provider default remains unchanged for other surfaces. Set
  `KIMETSU_CLAUDE_PERSISTENT=0` / `false` / `off` to force one-shot Claude
  subprocesses.
- **`kimetsu chat` reads the workspace `.env`.** Users can keep their own
  `CLAUDE_CODE_OAUTH_TOKEN` in `.env` under the `--workspace` directory;
  process environment variables still take precedence. See
  `docs/KIMETSU-CHAT.md`.
- **`multi_read` is native Rust.** It now batches all file slices through the
  `ToolRuntime` filesystem path instead of spawning shell, `sed`, `wc`, and
  `base64`.
- **Harbor `read_file` and `list_files` no longer shell out.** Both route
  through the runtime's workspace-safe filesystem helpers, removing process
  spawn overhead and quoting/path edge cases.
- **Chat reuses a brain session.** The REPL keeps one SQLite connection and
  loaded project config for the session instead of rediscovering and reopening
  the project on every user message.
- **Memory retrieval uses `memories_fts` first.** If the FTS table has no hit,
  retrieval falls back to the existing latest-memory scan.
- **Memory FTS joins by `memory_id`.** Older `brain.db` files are migrated in
  place from `(text, kind, scope)` joins to `memory_id UNINDEXED`, avoiding
  ambiguous text joins.
- **Manifest retrieval uses FTS.** `repo_manifests_fts` keeps manifest lookup
  from scanning every manifest row on each broker retrieval.
- **Hot brain queries use cached prepared statements.** This compounds with
  chat's persistent `BrainSession` connection.
- **Shell summaries cap before full string conversion.** Small successful
  shell commands no longer write duplicate artifacts; artifacts are kept for
  failures, timeouts, and larger outputs.
- **Tool trace fsync is configurable.** Durable fsync remains the default for
  pipeline runs; chat uses the faster non-fsync setting.
